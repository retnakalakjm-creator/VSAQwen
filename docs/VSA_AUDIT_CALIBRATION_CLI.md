# VSA Audit Calibration CLI

This document describes the audit-only command-line surface for turning saved `/api/vsa-audit/events` output into a compact Effort-vs-Result / absorption calibration summary.

The CLI does not load market data, does not run the scanner, does not change detector rules, does not change production scoring/ranking, does not persist decision context or journal entries, and does not touch broker, order, account, funds, holdings, margin, credential, or position-sizing scope.

## Why this CLI exists

PR #70 created the point-in-time VSA event audit endpoint.

PR #71 added `audit_flags` so exception rows can be filtered.

PR #72 added `detector_diagnostics` so high-volume reversal, absorption, Effort-vs-Result, Stopping Volume, and Spring/Shakeout candidates can be reviewed without treating them as confirmed production evidence.

PR #73 added the pure calibration helper.

This CLI makes the helper easy to use with a saved audit file such as `LT_New.txt`.

## Input

The input file must contain JSON returned by `/api/vsa-audit/events`.

The file extension does not matter. A `.txt` file is fine as long as its contents are JSON.

Example audit command to produce the input:

```text
http://127.0.0.1:8000/api/vsa-audit/events?symbols=LT.NS&start_week=2026-03-02&horizon_weeks=8
```

Save the response as something like:

```text
LT_New.txt
```

## Run the CLI

From the repository root:

```powershell
python scripts/vsa_audit_calibration_summary.py LT_New.txt
```

To write the summary to a file:

```powershell
python scripts/vsa_audit_calibration_summary.py LT_New.txt --output LT_calibration_summary.json
```

## Output

The CLI prints or writes the same compact summary generated by `build_effort_absorption_calibration_summary`:

- `rows`
- `priority_counts`
- `diagnostic_counts`
- `tag_counts`
- `symbol_counts`
- `audit_only: true`

Rows are selected when the audit output contains relevant detector diagnostics or context-mismatch audit flags.

Important tags include:

- `effort_gt_result_candidate`
- `absorption_candidate`
- `missing_bullish_reversal_event`
- `stopping_volume_candidate`
- `spring_shakeout_candidate`
- `qualification_conflict`
- `stale_evidence_review`
- `not_confirmed_by_current_detector`

## Guardrail

The CLI creates a review queue only. It is not a detector. It is not evidence. It is not a trading signal.

Production detector changes should still wait until the review queue has been tested across a wider symbol basket and false-positive set.
